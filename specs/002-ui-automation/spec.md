# Feature Specification: UI 自动化子系统

**Feature Branch**: `002-ui-automation`

**Created**: 2026-10-26

**Status**: Draft

**Input**: User description: "为 Pity API 测试平台新增基于浏览器自动化的 UI 测试能力，包含元素库、本地录制导入、UI 用例管理、执行与报告五个部分。录制的操作在用户本地完成再导入平台；平台内置执行节点；UI 用例与既有接口用例共用用例库与报告结构。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 沉淀元素定位并跑通第一条 UI 用例 (Priority: P1)

测试人员要验证一个 Web 页面上的登录流程。他知道该点哪个按钮、往哪个输入框填什么，但**不知道页面的元素定位**。

他先在平台的「元素库」里按页面组织被测界面——为「登录页」建一个页面条目，把「用户名输入框」「密码输入框」「登录按钮」三个元素登记进去，每个元素记录一条定位策略（CSS、XPath、ID、文本、Role、Placeholder、Label 之一）及其定位值。

然后他在项目下新建一条 UI 用例，步骤逐条引用元素库里登记好的元素（填用户名 → 填密码 → 点登录 → 校验错误提示文案）。执行这条用例，平台在真实浏览器中按步骤操作，逐步骤记录日志；成功则标记通过，失败则自动截图留存。

**Why this priority**: 这是整个子系统最小的可用闭环——不需要录制、不需要 AI，用户手工登记 + 手工编写 + 就能跑起来。元素定位独立于用例保存，是后面所有能力（录制导入、智能生成）的前提资产。

**Independent Test**: 手工登记一个页面与三个元素，编写一条引用它们并断言错误提示的 UI 用例，执行后能拿到逐步骤日志与通过/失败结论，即完成独立验证。

**Acceptance Scenarios**:

1. **Given** 用户进入元素库，**When** 新建一个页面并在其下登记元素，**Then** 页面出现在页面树中，元素归属于该页面并显示其定位策略与定位值
2. **Given** 用户选择定位策略为 Role，**When** 保存元素，**Then** 该元素可另外记录一个可访问名称，用于按角色与名称共同定位
3. **Given** 元素库中已存在某页面的某元素，**When** 用户新建一条引用该元素的 UI 用例，**Then** 用户可从元素库中选取该元素，无需手写定位表达式
4. **Given** 一条引用了三个元素的 UI 用例，**When** 用户执行该用例，**Then** 平台在浏览器中依次完成填充、填充、点击，并在断言处校验错误提示文案
5. **Given** 用例执行成功，**When** 用户查看执行详情，**Then** 每一步的动作、耗时与结果都被记录下来
6. **Given** 用例执行失败，**When** 用户查看执行详情，**Then** 失败步骤被明确指出，该用例附带一张失败时刻的页面截图
7. **Given** 页面改版导致某个元素定位不到，**When** 用例执行到该步，**Then** 失败信息明确指出是哪个元素、按哪种定位策略失效
8. **Given** 某元素已被停用，**When** 用户查看引用它的用例，**Then** 用户能看到该引用处于停用状态并可跳转处理
9. **Given** 用户尚未在项目下建立目录，**When** 用户尝试新建 UI 用例，**Then** 界面就地说明需要先建立目录及如何建立，而不是只报错
10. **Given** 用户填写的用例名称超出平台允许的长度，**When** 用户保存，**Then** 平台明确提示长度限制并给出建议的截断结果
11. **Given** 用例要访问的站点不在本项目的允许域名内，**When** 用户执行该用例，**Then** 平台拒绝执行并说明该域名未被允许，而不是照常发起访问
12. **Given** 用例要访问的域名虽然被允许，但解析到的是内网地址，**When** 用户执行该用例，**Then** 平台拒绝执行并说明目标地址被安全策略拦截
13. **Given** 本项目尚未配置任何允许域名，**When** 用户尝试执行 UI 用例，**Then** 平台明确说明尚未配置允许访问的域名并给出配置入口，而不是默认放行

### User Story 2 - 本地录制导入，快速产出可审核的用例草稿 (Priority: P2)

测试人员手工登记元素、编写步骤很慢，尤其是流程长的场景。

他改用本地录制：在自己的机器上用官方浏览器自动化工具操作一遍被测页面，把录制产出的脚本粘贴回平台的「录制导入」页面。平台解析这段脚本，**自动建立或复用对应的页面与元素**，并生成一条处于「调试中」的可编辑用例——用例里的每一步都已经指向元素库中登记好的元素。

用户核对步骤、调整步骤，确认无误后把用例状态改为「正常运行」即视为采纳。

**Why this priority**: 录制把"登记元素 + 编写步骤"这两件最费时的事压缩成一次本地操作 + 一次粘贴，是产用例效率提升最大的一环。但它依赖用户本地有相应工具，且导入结果仍需人工核对，所以排在手写闭环之后。

**Independent Test**: 本地录制一段登录操作、粘贴导入，检查平台自动建出的页面与元素、生成的用例步骤，修改步骤并保存后用例仍在用例库中，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户粘贴了一段录制脚本，**When** 平台解析该脚本，**Then** 生成一条处于「调试中」的可编辑用例，用例中每一步都已指向元素库中登记好的元素
2. **Given** 解析过程中遇到某个页面的元素尚不存在，**When** 平台建立元素，**Then** 该页面与元素被自动创建并出现在元素库中
3. **Given** 元素库中已存在同一个页面的同一个元素，**When** 再次导入同一段录制脚本，**Then** 平台复用既有元素，元素库中不产生重复条目
4. **Given** 录制脚本中含有平台无法解析的语句，**When** 平台解析该脚本，**Then** 这些语句被跳过并在导入结果中说明，整个导入不中断
5. **Given** 导入产生了一条处于「调试中」的用例，**When** 用户查看并编辑该用例的步骤后保存，**Then** 改动被保留且用例仍为「调试中」，直到用户确认无误改为「正常运行」
6. **Given** 录制的脚本中包含一段平台不予执行的自由代码，**When** 平台解析该脚本，**Then** 该段内容被拒绝解析，平台不会执行它
7. **Given** 用户粘贴的内容不是有效的录制脚本，**When** 平台解析，**Then** 平台明确说明无法解析的原因，并提示可改用的其他输入方式

### User Story 3 - 执行中心与测试报告 (Priority: P3)

测试人员跑完一轮 UI 回归，需要知道整体通过率、哪几条挂了、挂的那条错在哪。

他打开「执行中心」，看到正在执行的任务与历史执行记录——每条记录含执行时间、任务名称、环境、执行结果、用例数、通过率与执行人。他可以重新执行某次任务，也可以删除不需要的历史记录。

他点开某次执行的测试报告，看到总体通过率、逐日执行趋势，以及逐条用例的执行结果、错误信息、步骤日志与截图附件。

**Why this priority**: 结果呈现是交付价值的最后一环，但它建立在执行链路已经跑通的前提上，因此排在最后。报告与既有的接口测试报告共用同一套结构，不另起一套。

**Independent Test**: 执行一批 UI 用例后，在执行中心看到对应历史记录，打开其报告看到总体通过率与逐条用例结果（含失败用例的步骤日志与截图），即可独立验证。

**Acceptance Scenarios**:

1. **Given** 有一批 UI 用例执行完毕，**When** 用户打开执行中心，**Then** 历史执行记录列出执行时间、任务名称、环境、执行结果、用例数、通过率与执行人
2. **Given** 用户在执行中心看到一条历史记录，**When** 用户点击重新执行，**Then** 平台产生一次新的执行并生成新的历史记录，原记录不被覆盖
3. **Given** 用户不需要某条历史记录，**When** 用户删除它，**Then** 该记录从列表消失
4. **Given** 用户打开某次执行的测试报告，**When** 报告加载完成，**Then** 展示总体通过率与逐条用例的执行结果
5. **Given** 报告中有失败的 UI 用例，**When** 用户查看该条用例，**Then** 展示失败步骤的错误信息、逐步骤日志与失败时刻的截图
6. **Given** 同一项目中既有接口用例又有 UI 用例，**When** 用户查看报告，**Then** 两类用例的统计口径一致，通过率是合并计算的结果
7. **Given** 用户在执行中心切换到"正在执行"视图，**When** 有任务正在跑，**Then** 界面反映当前正在执行的任务及其进度

### Edge Cases

- **元素被删除但仍有用例引用**：该用例执行时明确报出缺失的元素，不得静默跳过或误判通过
- **元素被停用**：引用它的用例可见停用状态；执行时按停用语义处理并说明原因
- **元素定位失效**（页面改版）：失败信息须指明是哪个元素、按哪种定位策略失效，而不是笼统的"步骤失败"
- **单步超时**：该步骤判失败并保留现场，后续步骤不再执行
- **断言不通过**：用例判失败，但须保留失败前的完整步骤日志
- **目标页面打不开或加载超时**：用例判失败并截图，不应让执行卡死
- **浏览器异常退出**：该条用例判失败，不影响同批次其他用例，更不影响平台的其余功能
- **截图上传失败**：不影响用例的通过/失败判定，但须在日志中说明截图未留存
- **录制脚本含无法解析的语句**：跳过并说明，整段导入不中断
- **录制脚本含自由代码**：拒绝解析该部分，平台不执行其中任何内容
- **录制脚本重复导入**：不产生重复的页面与元素
- **用例名称或目录名称超出长度限制**：明确提示限制并给出建议的截断结果
- **项目下尚无目录**：就地提示需要先建目录及如何建
- **并发执行同一项目的多条 UI 用例**：各用例之间浏览器上下文互相隔离，不得互相污染登录态或数据
- **引用的元素在执行前被他人改动**：执行以执行时刻的元素定位为准
- **元素库为空时的智能生成**：明确告知需要先沉淀元素，不自行猜测定位（属 AI 工作台功能的约束）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持按页面组织被测界面，页面 MUST 构成树状结构并支持增删改查
- **FR-002**: 系统 MUST 支持在页面下维护元素，元素 MUST 归属于某个页面并支持增删改查
- **FR-003**: 每个元素 MUST 记录一条定位策略及其定位值；可用的定位策略 MUST 至少包括 CSS、XPath、ID、文本、Role、Placeholder、Label
- **FR-004**: 当定位策略为 Role 时，元素 MUST 支持额外记录一个可访问名称，用于按角色与名称共同定位
- **FR-005**: 元素 MUST 支持被停用；停用状态 MUST 在引用它的用例处可见
- **FR-006**: 系统 MUST 在同一页面、同一策略、同一定位值的情况下复用既有元素，不产生重复条目
- **FR-007**: UI 用例 MUST 与既有接口用例共用同一套用例库与目录树
- **FR-008**: UI 用例的步骤 MUST 由封闭的动作集合构成；集合之外的动作 MUST 被拒绝（**含 FR-041 所述的任意脚本执行**）
- **FR-009**: UI 用例的步骤 MUST 以引用元素库元素的方式表达定位
- **FR-010**: 系统 MUST 支持以内联定位作为兜底，但采纳时 MUST 提示建议将该定位纳入元素库
- **FR-011**: 引用了元素库中不存在或已停用元素的 UI 用例 MUST 被标出，且 MUST 在处理后才能执行
- **FR-012**: UI 用例 MUST 支持配置起始地址、单步超时与视口尺寸
- **FR-013**: 起始地址与步骤中的取值 MUST 支持引用环境级配置
- **FR-014**: 系统 MUST 支持用户粘贴录制脚本来导入录制结果
- **FR-015**: 导入时系统 MUST 自动建立或复用对应的页面与元素
- **FR-016**: 导入 MUST 产出状态为「调试中」的可编辑 UI 用例（**不新建草稿表**，复用既有用例状态语义），用户核对步骤并改为「正常运行」即视为采纳
- **FR-017**: 录制脚本中无法解析的语句 MUST 被跳过并在导入结果中说明，导入不中断
- **FR-018**: 录制脚本中的自由代码 MUST 被拒绝解析，系统 MUST NOT 执行其中任何内容
- **FR-019**: 系统 MUST 提供内置的执行节点，用户无需额外配置即可执行 UI 用例
- **FR-020**: 执行 MUST 支持无头模式与视口尺寸配置
- **FR-021**: 执行 MUST 逐步骤记录动作、耗时与结果
- **FR-022**: 用例执行失败时系统 MUST 自动留存失败时刻的页面截图
- **FR-023**: 元素定位失效时，失败信息 MUST 指明是哪个元素、按哪种定位策略失效
- **FR-024**: 单步超时 MUST 判定该用例失败、保留现场并停止后续步骤
- **FR-025**: 浏览器异常 MUST NOT 影响同批次其他用例，也 MUST NOT 影响平台的其余功能
- **FR-026**: UI 用例的执行结果 MUST 与接口用例共用同一套报告结构，不另建一套
- **FR-027**: UI 用例 MUST 支持单独执行（调试）与批量执行
- **FR-028**: 系统 MUST 提供执行中心，展示正在执行的任务与历史执行记录
- **FR-029**: 历史执行记录 MUST 包含执行时间、任务名称、环境、执行结果、用例数、通过率与执行人
- **FR-030**: 系统 MUST 支持对历史执行记录重新执行，且 MUST NOT 覆盖原记录
- **FR-031**: 系统 MUST 支持删除历史执行记录
- **FR-032**: 测试报告 MUST 展示总体通过率与逐条用例的执行结果
- **FR-033**: 测试报告 MUST 展示失败用例的错误信息、逐步骤日志与截图附件
- **FR-034**: 同一报告内接口用例与 UI 用例 MUST 采用一致的统计口径
- **FR-035**: 系统 MUST 在用例名称、目录名称超出平台长度限制时明确提示并给出建议的截断结果
- **FR-036**: 系统 MUST 在缺少目录、元素库为空等前置条件缺失时，在当前界面内给出可操作的指引（去哪里配、怎么建），用户 MUST NOT 需要离开当前页面自行寻找
- **FR-037**: 系统 MUST NOT 在本次范围内实现分布式执行节点与远程浏览器
- **FR-038**: 系统 MUST NOT 在本次范围内实现浏览器扩展录制通道
- **FR-039**: 系统 MUST NOT 在本次范围内实现服务端注入录制
- **FR-040**: 系统 MUST 保留移动端测试类型的位置但不在本次范围内实现
- **FR-041**: UI 用例的步骤 MUST NOT 包含任意脚本执行能力
- **FR-042**: 并发执行的 UI 用例 MUST 各自拥有隔离的浏览器上下文
- **FR-043**: UI 用例 MUST 只能访问项目级允许域名白名单内的站点；目标域名 MUST 通过白名单校验，且 MUST 拒绝解析到私有网段、环回、链路本地或保留地址的主机；跟随重定向时每一跳 MUST 重新校验
- **FR-044**: 允许域名白名单 MUST 为空时，该项目的 UI 用例 MUST 不可执行 —— 不得解释为"允许访问全部站点"

### Key Entities

- **页面**：被测界面的一个节点，构成树状结构，含名称、地址与上级页面
- **元素**：页面上的一个可定位对象，含名称、定位策略、定位值、可访问名称、所属页面与启用状态
- **UI 用例**：被测界面上的一个可执行流程，含步骤序列、起始地址、视口尺寸与超时；与接口用例同处一个用例库
- **步骤**：UI 用例中的一个动作，含动作类型、目标元素或定位、输入值与超时
- **用例草稿**：待审核的用例内容。本 feature 的"草稿"**指状态为「调试中」的 UI 用例**（`pity_testcase.status = 1`），复用既有用例状态语义，**不新建草稿表** —— 录制导入产出的用例先落在正式用例库里但保持「调试中」，用户核对步骤后改为「正常运行」即视为采纳 |
- **执行记录**：一次执行的汇总，含执行时间、任务名称、环境、结果、用例数、通过率与执行人
- **执行节点**：执行 UI 用例的运行环境，含在线状态、浏览器类型、无头模式与并发上限

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从完成本地录制到平台产出可审核的用例草稿，全程不超过 5 分钟
- **SC-002**: 同一段录制脚本导入两次，元素库中不产生任何重复条目
- **SC-003**: 页面改版导致定位失效时，失败信息在 30 秒内明确指出是哪个元素、按哪种定位策略失效
- **SC-004**: 在元素定位正确的前提下，单条 UI 用例的执行成功率不低于 95%
- **SC-005**: 失败的 UI 用例 100% 附带失败时刻的截图
- **SC-006**: 页面改版后需要手动修改的用例条数，相较于"同一批用例改用内联定位"时下降 90% 以上（基线口径：同一批用例在两种写法下，因该页面改版而需要改动用例的条数之比）
- **SC-007**: UI 用例与接口用例在同一份报告中的统计口径完全一致，通过率可合并计算
- **SC-008**: 任一历史执行记录 MUST 能追溯到逐条用例的结果与步骤日志
- **SC-009**: 用户在本次范围内无需安装任何浏览器扩展或平台侧附加组件即可完成录制导入与执行
- **SC-010**: 录制脚本中的自由代码 100% 未被执行
- **SC-011**: 平台 100% 拒绝访问不在项目允许域名白名单内的站点，以及解析到内网、环回或链路本地地址的站点
- **SC-012**: 录制导入产出的用例 100% 可被人工逐条编辑后采纳，编辑过程不丢失任何步骤

## Assumptions

- 目标用户是具备 Web 测试基础的测试人员，能够理解元素定位策略的含义并手工选择
- 用户在本机具备运行官方浏览器自动化录制工具的条件，录制在用户本地完成，平台只负责解析导入
- 平台已具备项目、目录、用例、测试报告与执行记录等既有结构，UI 用例沿用既有结构，不另建平行体系
- 平台已具备执行报告、执行计划调度与实时状态推送能力，UI 用例复用之
- 平台的部署环境能够运行真实浏览器；相关运行资源由部署方提供
- 智能生成 UI 用例的能力由另一个在建的 AI 工作台功能提供，且该功能只能引用元素库中已沉淀的元素定位
- 平台运行在受控环境内，但 UI 用例会驱动浏览器**主动访问外部站点** —— 目标地址由项目级允许域名白名单界定；**白名单为空时不放行**，而不是默认允许全部
- 本 feature 与 `001-ai-workbench` **互不依赖**：001 的公共层与草稿机制不依赖本 feature；本 feature 的元素库与执行链路也不依赖 001。跨 feature 的唯一耦合是 **001 的 Web UI 用例生成需要读取本 feature 的元素库**（单向），以及两者共用同一份步骤 DSL 契约（`contracts/steps.md`）
- 本功能不依赖智能生成能力即可独立使用：用户可全程手工登记元素、手工编写步骤并执行
- 用例的步骤集合是封闭的，集合之外的动作与任意脚本执行一律不接受
- 录制脚本的解析只识别有限的已知结构，不解析也不执行其中的自由代码
- 元素定位与用例的绑定关系意味着：元素定位被修改后，所有引用它的用例的行为随之改变，这是本功能的核心价值，也是需要用户留意的风险
- 并发执行的 UI 用例之间浏览器上下文互相隔离，单条用例的登录态不会影响其他用例
- 模块拆分、数据模型、步骤规范与设计取舍见 `backend/docs/ui-automation-design.md`（深设计附录）
