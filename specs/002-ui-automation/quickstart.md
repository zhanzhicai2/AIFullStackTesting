# Quickstart · 验证指南

> Feature: [UI 自动化子系统](./spec.md) | Plan: [plan.md](./plan.md) | 契约: [contracts/api.md](./contracts/api.md) · [contracts/steps.md](./contracts/steps.md)
> 本文件是**验收入口**：照着跑一遍，就能确认这个功能真的通了。

## 1. 前置条件

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 后端依赖 | `backend/.venv` 已装齐（含新增的 `playwright`） | `cd backend && .venv/bin/python -c "import playwright"` |
| 浏览器二进制 | chromium 已安装 | `cd backend && .venv/bin/playwright install chromium`（首次；或在 Docker 里用 `INSTALL_PLAYWRIGHT=1` 构建） |
| 数据库 | MySQL 可连；启动时自动建表（含 6 张新表） | 见 §2.1 |
| 对象存储 | 已配置（失败截图要传 OSS） | 后台「配置管理 → 对象存储」 |
| 被测站点 | 一个可访问的测试页面（**域名要能加进白名单**） | 自备，或用本地静态服务 |
| 全局变量 | 环境里配了 `${ui_base_url}`（站点根地址） | 后台「配置管理 → 全局变量」 |

> **本地跑 chromium 需要图形库**。无桌面环境用无头模式即可（默认 `headless = true`）。若 Playwright 报缺系统库，执行 `playwright install --with-deps chromium`（需要 root）。

## 2. 启动与准备

### 2.1 起后端

```bash
cd backend
source .venv/bin/activate
python pity.py            # 或 uvicorn main:pity --reload
```

启动日志应出现 6 张新表的建表信息：

```
pity_ui_page
pity_ui_element
pity_ui_case
pity_ui_node
pity_ui_import_log
pity_ui_allowed_domain
```

### 2.2 起前端

```bash
cd frontend
nvm use                   # 必须 Node 20（见 frontend/CLAUDE.md）
npm install --ignore-scripts
npm run start:dev         # localhost:8000
```

### 2.3 准备三样东西

1. **项目与目录** —— 建一个项目，在项目下建目录（UI 用例与接口用例共用这棵树）
2. **允许域名白名单** —— 在「UI 自动化 → 允许域名」里加一条被测站点的域名（如 `example.com`）。**不加则用例不可执行**，这是刻意设计
3. **全局变量** —— 在环境全局变量里配 `ui_base_url` = 被测站点根地址

## 3. 端到端验证场景

### 3.1 场景 A：元素库 → 手写用例 → 执行（最小闭环）

**这是最核心的一条，串起 FR-001 ~ FR-012 与 FR-018 ~ FR-027。**

**步骤**：

1. 进入「UI 自动化 → 元素库」，在项目下新建页面 `登录页`（填 URL）
2. 在该页面下新建三个元素：
   - `用户名输入框` · 策略 `Label` · 定位值 `用户名`
   - `密码输入框` · 策略 `Label` · 定位值 `密码`
   - `登录按钮` · 策略 `Role` · 定位值 `button` · 可访问名称 `登录`
3. **预期**：元素出现在该页面下，显示其定位策略与定位值
4. 再建一个**同名同策略同定位值**的元素
   - **预期**：提示元素已存在或返回既有元素 id，**元素库不出现重复条目**
5. 进入「UI 自动化 → 用例管理」，在目标目录下新建用例 `登录页-正常登录`：
   - `base_url` = `${ui_base_url}`
   - 步骤：`goto /login` → `fill 登录页.用户名输入框 = admin` → `fill 登录页.密码输入框 = 123456` → `click 登录页.登录按钮` → `expect_text 登录页.错误提示 = 用户名或密码错误`
6. 执行该用例
   - **预期**：逐步骤成功/失败可见，总耗时记录，断言处校验错误提示文案
7. **预期**：执行结果出现在测试报告里，**与接口用例同一套统计口径**
8. 停用 `登录按钮` 元素，再执行
   - **预期**：失败信息明确指出是哪个元素、按哪种策略失效，且该用例判失败
9. 重新启用 `登录按钮`，再执行 → **预期**：恢复正常

### 3.2 场景 B：本地录制导入（FR-014 ~ FR-017）

1. 在被测站点上本地跑：

   ```bash
   npx playwright codegen --target python https://example.com/login
   ```

   操作一遍（填用户名 → 点登录），把输出的 Python 脚本复制出来
2. 进入「UI 自动化 → 录制中心」，粘贴脚本 → 导入
3. **预期**：
   - 自动建出 `login` 页面
   - 自动建出元素（已存在的**复用**，不重复建）
   - 产出一条含步骤的用例
   - 若脚本含 `page.evaluate(...)` 这类行 → **该行被跳过并在结果里说明**，整段导入不中断
4. 再导入同一段脚本
   - **预期**：元素库**不产生任何重复条目**（SC-002）
5. 往脚本里塞一行 `import os; os.system('rm -rf /')`
   - **预期**：该行被跳过并说明。**平台绝不执行脚本内容**

### 3.3 场景 C：执行中心与报告（FR-028 ~ FR-034）

1. 执行一批 UI 用例
2. 进入「UI 自动化 → 执行中心」
   - **预期**：历史执行记录列出执行时间、任务名称、环境、结果、用例数、通过率、执行人
3. 点「重新执行」
   - **预期**：产生新的执行记录，**原记录不被覆盖**
4. 删除一条历史记录 → **预期**：从列表消失
5. 打开某次执行的报告
   - **预期**：总体通过率、用例执行趋势、逐条用例结果（结果 / 错误信息 / 步骤日志 / **截图附件**）
6. 同一项目里同时有接口用例与 UI 用例
   - **预期**：通过率是**合并计算**的，口径一致

### 3.4 场景 D：SSRF 边界（FR-043, FR-044）

**这条是安全验收，必须逐项走。**

| # | 操作 | 期望 |
|---|---|---|
| D1 | 用例的 `base_url` 指向一个**不在白名单**的域名 | 拒绝执行，明确说明该域名未被允许 |
| D2 | 白名单里加一个解析到 `127.0.0.1` 的域名 | 拒绝执行，说明目标地址被安全策略拦截 |
| D3 | 白名单里加 `169.254.169.254`（云元数据地址） | 拒绝执行 |
| D4 | 白名单里加一个域名，其页面 302 跳到内网地址 | **跳转那一跳被拦**，用例判失败，`error = navigation_blocked` |
| D5 | 清空白名单 | UI 用例**不可执行**，提示去配置，**不默认放行** |
| D6 | 白名单里加一个 `file:///etc/passwd` 之类的协议 | 拒绝，协议不被允许 |
| D7 | 页面里放一个 `<img src="http://169.254.169.254/x">` | 该子资源请求被浏览器层拦截 |

### 3.5 场景 E：并发隔离（FR-042）

1. 建两条 UI 用例，都做「登录后修改一个用户偏好」
2. 同时执行
   - **预期**：两条用例互不影响（各自独立 Context，登录态不串）

## 4. 就地指引点验证（constitution 原则 IV）

**这六条是 constitution 原则 IV 的落地验收，必须逐条走一遍。**

> **U1–U6 的唯一定义在 [`data-model.md` §5](./data-model.md#5-就地指引点constitution-原则-iv)**，本节只做验证，不重复定义。

| 编号 | 操作 | 期望 |
|---|---|---|
| **U1** | 清空白名单 → 打开用例执行 | 就地提示「尚未配置允许访问的域名」+ 配置入口；执行按钮不可用 |
| **U2** | 删掉全局变量 `ui_base_url` → 打开用例编辑器 | base_url 字段旁提示站点地址未配置 + 跳转全局变量页 |
| **U3** | 选一个没有目录的项目 → 新建 UI 用例 | 目录选择器旁有「新建目录」入口，就地建完即选中 |
| **U4** | 在空元素库的项目下 → 打开用例编辑器 | 元素选择处提示「元素库为空，先沉淀页面与元素」+ 跳转元素库 |
| **U5** | 打开录制导入页但不粘贴脚本 | 导入区提示粘贴录制脚本，或改用手工新建 |
| **U6** | 把唯一节点置为离线 → 点执行 | 提示「没有可用的执行节点」+ 跳转节点页 |

## 5. 回归脚本

constitution 原则 V：**落地前 MUST 通过自动化验证**。

```bash
cd backend
.venv/bin/python scripts/ui_selftest.py    # 解析器/DSL 校验/定位映射, 不需要浏览器
.venv/bin/python scripts/ui_e2e.py         # 端到端, 需要后端在跑 + 本地 chromium
```

| 脚本 | 覆盖 |
|---|---|
| `selftest` | codegen 脚本解析（sync/async、各种 locator、无法解析的行）；元素去重；步骤 DSL 校验（动作白名单、必填字段、策略枚举）；**动作白名单的负例**（`evaluate` / `exec` 必须被拒绝）；SSRF 拦截（私网地址、环回、链路本地、非 http 协议、重定向逐跳校验）；等待策略（禁止隐式 sleep 与随机退避） |
| `e2e` | 页面/元素 CRUD；元素去重与停用；录制导入 → 用例生成；UI 用例执行 → `pity_test_result` 回写；失败截图落 OSS；**SSRF 拦截在真实执行期生效**；并发上下文隔离；与接口用例混合执行时的报告统计口径 |

前端验收：

```bash
cd frontend
nvm use
npx tsc --noEmit          # 目标 0 错误
npm run lint:js
```

## 6. 验收标准对照

| 成功标准 | 怎么验 |
|---|---|
| SC-001 从完成本地录制到平台产出可审核的用例草稿 ≤ 5 分钟 | 场景 B 计时，3 次取中位数 |
| SC-002 同一段录制脚本导入两次，元素库不产生重复条目 | 场景 B 步骤 4 逐条比对元素列表 |
| SC-003 定位失效时 30 秒内指出是哪个元素、哪种策略 | 场景 A 步骤 8 计时（失败信息出现的时刻） |
| SC-004 元素定位正确时单条用例执行成功率 ≥ 95% | 场景 A 的用例连跑 20 次统计 |
| SC-005 失败的 UI 用例 100% 附带失败时刻截图 | 场景 A 步骤 8 检查附件 |
| SC-006 页面改版后需手动修改的用例条数，相较于"同一批用例改用内联定位"时下降 90% 以上 | **基线口径**：同一批用例在两种写法下，因该页面改版而需要改动用例的条数之比。做法：① 复制一批用例为「内联定位版」与「元素库版」；② 模拟一次该页面的元素改版；③ 分别统计两边需手动改动的用例条数 |
| SC-007 UI 与接口用例在同一报告中的统计口径完全一致 | 场景 C 步骤 6 |
| SC-008 任一历史执行记录能追溯到逐条用例结果与步骤日志 | 场景 C 步骤 5 |
| SC-009 无需安装任何浏览器扩展或平台侧附加组件即可完成录制导入与执行 | 场景 B 全程未安装扩展 |
| SC-010 录制脚本中的自由代码 100% 未被执行 | 场景 B 步骤 5 |
| SC-011 平台只访问允许域名内的站点，且拒绝内网地址 | 场景 D 全表 |
| SC-012 录制导入产出的用例可被人工逐条编辑后采纳 | 场景 B 产出后编辑步骤并保存 |

> **判定口径说明**：本 feature 的 SC 以**可自动/可重复验证**为主（12 条里有 10 条是客观计数），与 `001-ai-workbench` 的抽样人工判定口径不同，故不套用其 §6.2。
>
> 唯一带主观判断的是 SC-004 的"执行成功率"与 SC-006 的"需改动条数" —— 前者以"元素定位正确"为前提（否则失败是页面问题不是平台问题），后者按上面写明的基线口径计数。
> 通用的人工判定抽样口径见 [`001-ai-workbench` 的 quickstart §6.2](../001-ai-workbench/quickstart.md#62-需人工判定的标准含抽样口径)，若将来本 feature 增加主观型 SC，按该口径执行。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示"目标域名不在允许列表内" | 白名单没配或域名不匹配 | 「允许域名」页加上该域名（注意是裸域名，不带 `https://`） |
| 提示"目标地址解析到内网地址" | 域名解析到了 127.x / 10.x / 169.254.x | 换公网域名，或确认本地测试服务的处理方式 |
| 提示"没有可用的执行节点" | 节点离线 | 检查「执行节点」页；v1 只有内置节点，重启后端会自动注册 |
| 浏览器启动失败，缺系统库 | 环境没装 chromium 依赖 | `playwright install --with-deps chromium` |
| 元素定位到多个 | 定位策略不够精确 | 换更精确的策略，或在元素定义里指定索引 |
| 导入的脚本只解析出几步 | codegen 输出含多行调用或自定义 JS | 看导入结果里的 warnings，跳过的行会说明原因 |
| 用例一直卡在某步 | 元素没出现，条件等待在等 | 看该步耗时是否等于超时值；这是**真实的失败**，不是平台的问题 |
| 截图没生成 | 对象存储没配 | 后台「配置管理 → 对象存储」配置后重跑 |
