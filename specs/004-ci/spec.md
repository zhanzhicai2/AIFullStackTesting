# Feature Specification: 持续集成（外部 CI 对接）

**Feature Branch**: `004-ci`

**Created**: 2026-11-23

**Status**: Draft

**Input**: User description: "specs/004-ci —— 持续集成（外部 CI 对接）。上游输入：specs/004-ci/proposal.md（已确认，§9 五项决定为硬约束）"

## 背景

前端路由表里已有 `/ci` 一级菜单（「持续集成」），当前指向「努力建设中」占位页；后端没有任何 CI 相关接口或数据。本特性把这块空地做成**平台对外的测试执行通道**：Jenkins、GitHub Actions、GitLab CI 等外部流水线在构建过程中调用平台，触发指定的测试计划，拿到「通过 / 未通过」的明确结论并据此阻断或放行流水线；平台侧留下可追溯的触发记录，并在 `/ci` 页面上完成凭据签发、接入示例复制与历史查询。

**定位（已确认）**：**外部 CI 对接** —— 平台是被调用的一方。**不是**平台自己监听代码仓库事件、自己编排流水线（该方向列为二期备选，本规格不覆盖）。

**五项已拍板决定**（`proposal.md` §9，本规格的输入约束，写需求时不得偏离）：

| # | 决定 |
|---|---|
| Q1 | 未来的回调地址允许指向内网，但走「项目级主机白名单 + 仅管理员配置」；**一期不发送回调** |
| Q2 | 业务结果码取 `111`（测试未通过），紧邻既有 `110` 递增，落在既有同区段 |
| Q3 | 触发默认为**不等待、可查询**；「等待完成」作为可选项，且必须有时间上限 |
| Q4 | 凭据默认有效期 **1 年**，可设为长期有效 |
| Q5 | **一期不做回调 webhook**，只做「触发 + 判定 + 记录」闭环 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 签发并管理接入凭据 (Priority: P1)

项目管理员进入 `/ci` 页面，选择所属项目，新建一条集成配置并命名（例如「Jenkins-main」）。平台生成一串长期有效的接入凭据，**只在创建成功的那一刻完整展示一次**，此后列表里只显示可辨识的前缀。管理员可以为这条配置绑定一个默认测试计划、停用（吊销）它、或删除它；页面同时显示这条凭据最后一次被使用的时间。

**Why this priority**: 没有可用凭据，外部流水线根本进不来。这是整条链路的第一块地基，也是用户面对的第一个界面 —— 它单独交付就已经消除了「完全无法接入」的状态。

**Independent Test**: 在一个项目下走「新建集成 → 拿到凭据 → 列表可见前缀 → 停用」完整一遍，即可独立验证本故事交付价值。

**Acceptance Scenarios**:

1. **Given** 用户是该项目的管理员，**When** 他新建一条集成配置并命名，**Then** 平台返回一次性的完整凭据，且列表中只展示该凭据的可辨识前缀
2. **Given** 凭据已签发，**When** 用户回到列表页刷新，**Then** 完整凭据不再出现，无法通过任何界面重新查看
3. **Given** 用户为集成配置绑定了默认测试计划，**When** 后续外部触发不指定计划，**Then** 平台使用该默认计划执行
4. **Given** 一条集成配置处于停用状态，**When** 外部系统用它的凭据发起调用，**Then** 平台拒绝并明确告知凭据已停用，不执行任何测试
5. **Given** 凭据已超过有效期，**When** 外部系统用它调用，**Then** 平台拒绝并明确告知已过期
6. **Given** 用户为凭据设置为长期有效，**When** 时间推移超过一年，**Then** 该凭据仍可用
7. **Given** 凭据近期被成功调用过，**When** 用户查看集成配置列表，**Then** 页面显示最近一次使用时间
8. **Given** 用户没有该项目的管理权限，**When** 他尝试查看或管理集成配置，**Then** 平台拒绝该操作，凭据信息不对其可见

---

### User Story 2 - 流水线触发测试并据此阻断 (Priority: P1)

CI 工程师把一段现成的流水线片段贴进项目的 Jenkinsfile / GitHub Actions 配置：带上平台地址与凭据，指定要跑的测试计划，附上本次构建的构建号。流水线执行到该步骤时调用平台，平台跑完测试计划后给出结论 —— 通过则流水线继续，未通过则该步骤失败、流水线变红。工程师也能选择「调完立即返回、由流水线稍后查询结果」的方式，以适应长耗时的测试。

**Why this priority**: 这是本特性的核心价值 —— 让测试结论真正卡在交付流程上。US1 只是地基，没有 US2，凭据毫无用处。两者合起来构成可独立演示的 MVP。

**Independent Test**: 用一份真实流水线配置触发一次含失败用例的测试计划，核对流水线确实变红；再触发一次全通过的计划，核对流水线继续，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 凭据有效且计划属于该项目，**When** 外部系统携带凭据与计划发起触发，**Then** 平台开始执行该测试计划，并返回本次执行的唯一标识
2. **Given** 测试计划执行完毕且全部用例通过，**When** 调用方读取本次结果，**Then** 结果明确表达「通过」，流水线继续执行后续步骤
3. **Given** 测试计划执行完毕但存在失败或异常用例，**When** 调用方读取本次结果，**Then** 结果明确表达「未通过」，调用方据此让流水线失败
4. **Given** 调用方选择等待执行完成，**When** 执行在设定的时间上限内完成，**Then** 调用方在一次返回中同时拿到结论、各状态用例数、通过率与报告入口，无需再次查询
5. **Given** 调用方选择等待执行完成但执行超出时间上限，**When** 到达上限，**Then** 平台明确告知「已超时、执行仍在继续」，后台执行不被中断，调用方仍可凭本次标识查到最终结果
6. **Given** 调用方选择不等待，**When** 触发被接受，**Then** 平台立即返回本次执行标识，调用方随后可凭它查询到进行中或已完成的结果
7. **Given** 平台自身执行出现故障（计划不存在、数据不可用、执行崩溃），**When** 调用方读取结果，**Then** 结果明确表达「执行失败」而非「测试未通过」，两者在结果上可区分
8. **Given** 凭据无效、已过期、已停用，**When** 外部系统发起触发，**Then** 平台拒绝执行，且拒绝原因可区分（无效 / 过期 / 已停用）
9. **Given** 凭据属于项目 A，**When** 调用方试图触发项目 B 的测试计划，**Then** 平台拒绝执行并说明越权，不执行任何测试
10. **Given** 指定的测试计划不存在或已删除，**When** 调用方发起触发，**Then** 平台拒绝执行并说明计划不可用
11. **Given** 同一测试计划已有一份执行在进行中，**When** 调用方再次触发同一计划，**Then** 平台拒绝重复触发并说明原因，不产生并发的第二份执行
12. **Given** 测试计划内一个用例都没有，**When** 执行结束，**Then** 结果不得表达为「通过」，而应明确提示计划为空、无法判定
13. **Given** 测试计划配置了多个执行环境，**When** 调用方触发，**Then** 平台按计划配置执行全部环境，并在结果中汇总各环境结论

### User Story 3 - 追溯触发历史与结果 (Priority: P2)

测试负责人打开 `/ci` 页面的触发历史，按项目与时间范围翻页查看：什么时候、用哪条凭据、跑了哪个计划、外部流水线的构建号是多少、结果如何、报告在哪里。点外部构建号可以跳回流水线页面，点报告入口可以进入既有的测试报告详情。

**Why this priority**: 触发记录让「上周那次构建为什么红了」可以被回答，是 CI 接入的可运营性保障。但它依赖 US2 已经产生数据，且不阻塞核心闭环，故排 P2。

**Independent Test**: 连续触发两次不同结果的执行，在历史列表中按项目筛选并核对两条记录的字段与跳转，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 一次触发已完成，**When** 用户查看触发历史，**Then** 该记录包含触发时间、凭据、项目、计划、环境、结果、耗时与报告入口
2. **Given** 调用方触发时附带了外部构建标识与外部地址，**When** 用户查看历史，**Then** 两者被展示，点外部地址可跳转到对应流水线页面
3. **Given** 执行仍在进行中，**When** 用户查看历史，**Then** 该记录明确显示为进行中，而非空白或误判为失败
4. **Given** 历史记录超过一页，**When** 用户翻页，**Then** 列表正确分页且不重复、不遗漏
5. **Given** 用户按项目筛选，**When** 应用筛选，**Then** 只返回该项目的记录，不跨项目泄露
6. **Given** 一次执行已结束，**When** 用户点报告入口，**Then** 进入既有的测试报告详情页并能看到本次执行的用例明细

---

### User Story 4 - 一键复制接入示例 (Priority: P2)

CI 工程师在 `/ci` 页面选中一条集成配置后，直接看到可粘贴的 Jenkinsfile 片段与 GitHub Actions 工作流片段，平台地址、计划名等已自动填好，凭据位置给出明确占位与提示。他点「复制」即可粘进自己的流水线仓库，不需要去翻文档、也不需要手拼 URL。

**Why this priority**: 接入成本几乎完全取决于「能不能照抄」。但它是 US1/US2 的加速器而非地基 —— 手工拼 URL 也能接上，只是慢。故排 P2。

**Independent Test**: 在页面上选中配置并复制示例，粘贴到空白流水线文件中，核对占位符与结构完整，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户选中一条集成配置，**When** 页面展示接入示例，**Then** 示例中的平台地址与计划名已自动填为当前配置的真实值
2. **Given** 示例需要凭据，**When** 页面展示，**Then** 凭据位置以占位符呈现并提示去哪里取，**不**把完整凭据回显进示例
3. **Given** 用户点击复制，**When** 复制完成，**Then** 剪贴板内容与页面展示一致，且有复制成功的反馈
4. **Given** 用户尚未选择任何集成配置，**When** 打开接入示例区，**Then** 页面就地提示先创建集成配置并给出入口，而不是展示一段缺字段的残缺示例
5. **Given** 当前项目下一个测试计划都没有，**When** 用户查看示例，**Then** 页面就地提示先创建测试计划并给出入口

---

### Edge Cases

- **凭据在执行过程中被吊销**：已开始的执行应正常跑完（吊销阻止的是新调用），但吊销后不得再接受新的触发。
- **执行期间平台重启**：本次执行会中断，历史中的记录 MUST 落到「失败/中断」而非永久停留在「进行中」；调用方轮询时 MUST 能得到终态。
- **调用方在等待期间断开连接**：等待模式下连接中断不应导致执行被取消，执行继续完成且结果可查。
- **同一外部构建号重复触发**：允许多次触发，历史中各自成条，不覆盖、不合并。
- **凭据明文被误录进日志**：凭据不得以完整形态出现在平台日志与操作日志中。
- **计划内全部用例被跳过**：结果 MUST 不得表达为「通过」。
- **测试计划的执行人字段为系统**：历史中应能看出是外部 CI 触发，而非某个真人点了执行按钮。
- **凭据长期无人使用**：页面应能通过「最后使用时间」暴露闲置凭据，便于回收。

## Requirements *(mandatory)*

### Functional Requirements

**接入凭据**

- **FR-001**: 项目管理员 MUST 能为指定项目签发接入凭据，用于外部系统非交互式调用平台。
- **FR-002**: 凭据完整明文 MUST 仅在签发成功时展示一次；此后任何界面 MUST NOT 再次展示完整明文，只展示可辨识前缀。
- **FR-003**: 凭据 MUST 可被停用（吊销），停用后 MUST 立即拒绝新的调用。
- **FR-004**: 凭据 MUST 有有效期，默认 1 年；MUST 支持设置为长期有效（无到期日）。
- **FR-005**: 凭据 MUST 绑定项目作用域；用 A 项目的凭据触发 B 项目的测试计划 MUST 被拒绝。
- **FR-006**: 凭据 MUST 可绑定一个默认测试计划；未绑定默认计划时，调用方 MUST 显式指定计划。
- **FR-007**: 系统 MUST 记录并展示每条凭据的最后使用时间。
- **FR-008**: 凭据 MUST NOT 以完整明文形式持久化到平台存储中。

**触发与判定**

- **FR-009**: 外部系统 MUST 能凭有效凭据触发指定测试计划，全程无需浏览器登录。
- **FR-010**: 触发 MUST 支持两种等待语义：等待完成并返回结论，或立即返回标识、稍后查询。**默认为后者**。
- **FR-011**: 等待语义 MUST 有时间上限；到上限时 MUST 明确告知调用方已超时，且 MUST NOT 中断仍在进行的执行。
- **FR-012**: 每次被接受的触发 MUST 产生唯一可查询的执行标识。
- **FR-013**: 执行结束 MUST 回传：是否通过、成功/失败/异常/跳过用例数、通过率、以及测试报告入口。
- **FR-014**: 调用方 MUST 能仅凭一次返回结果判断「继续还是阻断流水线」，无需额外请求（等待语义下）。
- **FR-015**: 「测试未通过」与「平台执行失败」MUST 在结果上可区分 —— 前者是测试结论，后者是系统故障。
- **FR-016**: 凭据无效、已过期、已停用、越权、计划不可用、重复触发 —— 这些拒绝情形 MUST 各自给出可区分的原因。
- **FR-017**: 同一测试计划已有执行在进行中时，MUST 拒绝重复触发并说明原因，MUST NOT 产生并发的第二份执行。
- **FR-018**: 测试计划内没有任何用例时，结果 MUST NOT 表达为「通过」，MUST 明确提示无法判定。
- **FR-019**: 测试计划配置了多个环境时，MUST 按计划配置执行全部环境，并在结果中汇总。

**触发记录**

- **FR-020**: 每次触发 MUST 留下记录：触发凭据、项目、计划、环境、起止时间、结果、耗时、报告入口。
- **FR-021**: 记录 MUST 接受调用方传入的外部构建标识与外部地址，并在历史中展示、可跳转。
- **FR-022**: 触发历史 MUST 支持按项目与时间范围查询并分页。
- **FR-023**: 记录 MUST 能区分「进行中」「成功」「失败」「超时」「执行失败」五种终态。
- **FR-024**: 平台日志与操作日志 MUST NOT 记录完整凭据明文。

**前端页面**

- **FR-025**: `/ci` 路由 MUST 指向真实页面，不再是占位页。
- **FR-026**: 页面 MUST 包含三个区域：集成配置、接入示例、触发历史。
- **FR-027**: 接入示例 MUST 支持一键复制，且 MUST 自动填入平台地址与计划名；凭据位置 MUST 以占位符呈现，不回显完整明文。
- **FR-028**: 凭据的签发、停用、删除 MUST 限定管理员及以上角色。
- **FR-029**: 页面在缺少前置条件（未选项目、无集成配置、无测试计划）时 MUST 就地给出指引与入口，MUST NOT 只报一句「请先选择」。

**边界与回归**

- **FR-030**: 凭据在执行开始后被吊销时，已开始的执行 MUST 正常完成，但 MUST NOT 再接受新调用。
- **FR-031**: 执行期间平台重启时，该次执行的记录 MUST 落到终态，MUST NOT 永久停留在「进行中」。
- **FR-032**: 调用方在等待期间断开连接 MUST NOT 导致执行被取消。
- **FR-033**: 本特性 MUST 通过自动化回归验证（含不依赖数据库的核心链路断言与依赖数据库的端到端断言），MUST NOT 只靠手动点一遍。

### Key Entities

- **集成配置（凭据）**: 某个项目对外接入的凭证与约束。关键属性：所属项目、名称、凭据本体（以不可还原形式保存，界面只展示可辨识前缀）、绑定的默认测试计划、启用状态、有效期、最后使用时间。
- **执行记录**: 一次外部触发的完整生命周期。关键属性：所用集成配置、项目、计划、环境、外部构建标识、外部地址、状态（进行中/成功/失败/超时/执行失败）、各状态用例计数、通过率、起止时间、耗时、产生的测试报告入口。
- **测试计划**: 既有实体（项目、环境集合、用例集合、执行顺序、重试策略），本特性只消费不改造。
- **测试报告**: 既有实体，由执行产生，本特性只引用其入口不改造其结构。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 项目管理员从进入 `/ci` 页面到复制出可运行的流水线片段，MUST 在 **3 步操作**内完成。
- **SC-002**: 从管理员签发凭据到首条外部流水线成功跑通，MUST 在 **10 分钟**内完成（含片段粘贴）。
- **SC-003**: 等待语义下，测试执行结束后调用方 MUST 在 **5 秒内**拿到可判定的结论。
- **SC-004**: 等待语义下，判断「继续 / 阻断」所需的结果读取次数 MUST 为 **1 次**。
- **SC-005**: 触发记录完整率 MUST 为 **100%** —— 每一次被接受的触发都能在历史中查到对应记录与报告入口。
- **SC-006**: 「测试未通过」与「平台执行失败」的可区分率 MUST 为 **100%**，无一例混淆。
- **SC-007**: 平台存储与日志中完整凭据明文的出现次数 MUST 为 **0**。
- **SC-008**: 越权、过期、停用、无效凭据的拒绝率 MUST 为 **100%**，且原因可区分。
- **SC-009**: 触发历史在常规数据量（单项目 1000 条内）下 MUST 在 **1 秒内**返回一页。
- **SC-010**: 同一测试计划的并发重复触发 MUST **0 次**成功产生第二份并行执行。
- **SC-011**: 自动化回归 MUST 覆盖「签发凭据 → 触发 → 拿到结论 → 查到记录」的完整端到端路径，且在每次改动后可重复执行全绿。
- **SC-012**: 一位未参与开发的 CI 工程师 MUST 能仅凭页面上的接入示例完成接入，无需额外文档。

## Assumptions

- **一期不做回调 webhook**（决定 Q5）。外部系统通过等待返回或轮询获取结果；结果主动推回流水线的能力留待二期。
- **回调地址允许指向内网**（决定 Q1），但必须走「项目级主机白名单 + 仅管理员配置」；该约束在一期体现为凭据配置中预留回调地址字段、仅保存不发送。
- **业务结果码取 `111`**（决定 Q2），表达「测试未通过」，与既有业务码表同区段递增，不影响既有前端对成功码的判定。
- **触发默认不等待**（决定 Q3），等待模式为可选项且必须有时间上限。
- **凭据默认有效期 1 年**（决定 Q4），可设为长期有效。
- **测试计划、测试报告、执行引擎均为既有能力**，本特性只消费不改造其表结构与语义。
- **平台按单进程部署形态运行**，长耗时执行不得依赖增加进程数来消化等待连接。
- **既有定时调度与手工执行计划的入口行为保持不变**，本特性新增独立的外部触发通道，不改造既有入口。
- **执行结果不可重放**（与既有 UI 自动化、接口测试同源约束）：测试结论取决于被测系统的状态，文档与界面需显式标注。
- **凭据粒度为项目级**：不提供「只允许触发单条计划」的更细粒度限制（通过绑定默认计划提供引导，但不做强制）。
- **范围外**：代码质量门禁、覆盖率统计、制品归档、Git 事件监听、内建流水线编排、精准测试。
